# Upstream sources

## Saved workstations and project setup (2026-09-20)

Reuses the existing group/project API, React Flow chart, shadcn form components, native OpenSSH bridge and SQLite state. Project membership editing moved from GroupDialog into the Structure page; it does not introduce a second membership store.

SSH authentication follows [OpenSSH's documented config/key/password behavior](https://man.openbsd.org/ssh.1) and its [readpass.c SSH_ASKPASS contract](https://github.com/openssh/openssh-portable/blob/master/readpass.c). The platform executable acts as its own bounded askpass helper; no password is placed in SSH arguments or environment values. Encryption uses the Windows [CryptProtectData / DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) API through the already resolved `windows-sys` crate, now declared directly. No SSH implementation or encryption algorithm is reimplemented. Native `ssh-keyscan` plus the existing SHA-256/base64 dependencies supplies reviewed host fingerprints; StrictHostKeyChecking stays enabled.

Password acceptance uses the installed [Paramiko ServerInterface](https://docs.paramiko.org/en/stable/api/server.html) as a temporary loopback SSH endpoint, forwarding actual bridge requests to the existing workstation. It supplies real password authentication without changing remote users or credentials. This is a test-only dependency; it is not part of the deployed transport.


## Agent questions (2026-09-20)

Question IDs, headers, choices and the `{answers: {question_id: {answers: [...]}}}` response shape follow [openai/codex's request-user-input protocol](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/request_user_input.rs). This is a protocol adaptation through the platform's existing `enterprise` MCP server and native Codex client, retaining its exec/resume sessions. [Official non-interactive documentation](https://learn.chatgpt.com/docs/non-interactive-mode) describes exec JSON events/MCP; [app-server documentation](https://learn.chatgpt.com/docs/app-server) documents its separate `item/tool/requestUserInput` request/response channel. The platform does not implement that app-server channel or terminal keystroke forwarding.

Persistence, owner-only API authorization, idempotency, SSE updates and process cancellation reuse the existing action/tool infrastructure. shadcn buttons/textarea and ordinary forms render the questions; suggested choices remain editable. No new dependency, provider, approval bypass or second runtime was introduced.
